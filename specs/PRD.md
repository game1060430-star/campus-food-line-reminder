# PRD — 校園食材登錄自動化系統

## 1. 產品目標
把校園食材登錄的日常工作從「每天手動登入、切頁、填資料、上傳」改成「只處理例外」。

正常情境：營業日與菜單固定，系統自動產生資料、檢查、上傳、確認成功。
異常情境：菜單變更、缺少必填資料、Session 過期、CAPTCHA、官方上傳失敗時才通知使用者。

## 2. 使用者與權限
- Owner/Admin：可看所有分店、設定官方帳密、修改主檔、菜單、上傳。
- Store Manager：可管理被授權分店的菜單、進貨與資料。
- Staff（可選）：只可新增進貨或查看，不可改帳密/全域設定。
- LINE User ID 與系統帳號綁定；未綁定者不得操作敏感功能。

## 3. 分店
每店保存：
- 分店顯示名稱
- 學校名稱（必要）
- 供餐地點（必要）
- 餐廳名稱（必要）
- 官方平台帳號
- 官方平台密碼（加密）
- 時區（預設 Asia/Taipei）
- 營業星期
- 預設未來預排天數（預設 30）
- 是否啟用自動產檔/自動上傳/LINE 異常通知

## 4. 主檔
### 4.1 供應商
最低只要求名稱。負責人、統編、地址、電話都選填。

### 4.2 食材
主檔保存相對固定資料：產品名稱、食材名稱、原產地、預設供應商，以及使用者選擇保存的製造商/加工食品/GMO/標章/單位/熱量等。

進貨批次保存：進貨日期（必要）、生產日期、有效日期、批號、重量、供應份數等。

### 4.3 調味料
主檔：調味料名稱、預設供應商，以及選填製造商、產品名稱、標章、單位、GMO、加工品等。
批次：進貨日期、開始日期、結束日期（必要），其他選填。

### 4.4 菜色
- 菜色名稱（必要）
- 類別（選填）
- 熱量（官方預排菜單必要；可設定預設值）
- 多個食材
- 多個調味料
- 每份用量選填
- 啟用/停用，不硬刪歷史使用過的菜色

## 5. 菜單排程
支援：
- 單日
- 多日期勾選
- 日期區間 + 指定星期
- 只套用營業日
- 複製昨天
- 複製上週同日
- 固定平日模板
- 未來 N 天 rolling schedule

新增/刪除/修改菜色後，只把受影響日期標為 dirty/pending，不影響其他日期。

## 6. LINE OA / LIFF
LINE 是主入口。
Rich menu 至少：今日狀態、菜單、新增菜色、進貨、食材/調味料、上傳狀態。
複雜表單在 LIFF 開啟，完成後回 LINE 顯示結果。

自然語言指令可作為輔助，例如：「下週一到五 A店加鹽烤豬五花」，但解析後先回傳變更摘要，由使用者按確認才正式寫入。

## 7. 上傳中心
每個日期/分店/檔案類型都有狀態：
- draft
- invalid
- pending
- running
- waiting_captcha
- success
- failed
- superseded（資料後來又修改）

首頁優先顯示黃色/紅色例外，不讓正常成功項目佔滿畫面。

## 8. 通知
只在需要人介入時主動 LINE：
- CAPTCHA
- 登入失敗
- 必填資料缺漏
- 官方上傳失敗
- 營業日應登錄但尚未成功
可設定每日一次成功總結。
